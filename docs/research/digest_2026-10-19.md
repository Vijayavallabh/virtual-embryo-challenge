## Part 1. Scorer and board mechanics (cross-cutting, all verified)

- **Aggregation.** T1 weights .25 de_score / .25 de_direction / .30 mmd_u / .20 variogram. T3 weights .30 de_score /
  .25 de_direction / .25 |severity_slope| / .20 distribution (mmd_u 0.6, variogram 0.4). T2 board =
  25*expr + 25*dist + 25*mean(d2_shape, occupancy_dice, |scale_log_ratio|) * gate + 25*neighborhood_mmd, with the
  structure gate `g = min(1, skill(neighborhood_mmd)/0.5)`. Fits 608 T2 rows, 203 T1 and 204 T3 to <=1e-4; a plain
  product gate is off by up to 10.3 points.
- **Overall.** Total = T1 + T2 + T3, where the T2 task score divides by a fixed 3 on the validation boards (exact on
  all 388 rows); in the final phase T2 has two boards, so each carries half the weight of T1 or T3.
- **Skill map.** `skill = 1/(1+x)`, x = remaining fraction of the floor-to-ceiling gap. Halving the distance to the
  ceiling gives 0.667.
- **The gate only bites below the floor.** On heart extrapolation some rows sit below nbhd skill 50 and lose shape
  credit (count and cost: [per-board leaderboard figure removed 2026-11-05; docs/DATA_POLICY.md 2026-11-05 (h)]);
  "up to 25 points" is a theoretical bound. Keeping expression attached to positions protects it.
- **Severity (T3).** A wrong sign, beta <= 0, or R^2 <= 0.01 returns `log(1e-3) = -6.9078`, which equals the published
  floor: skill 0.5, i.e. 50, not 0. Any beta > 0 with R^2 > 0.01 scores 0.6-1.0; beta in [0.5, 2] gives >= 0.91.
  Getting the sign right is worth up to ~12.5 T3 points with no downside — **but** note two corrections: (a) the
  Evaluation page and the proposal call that case "undefined", which would map to skill 0 and make a wrong sign cost
  another 12.5 points — nobody has asked which rule the final evaluation uses; (b) a correct-sign prediction that adds
  a shared global offset to the DE genes can still hit R^2 <= 0 and the floor (verified: adding an offset gave
  R^2 = -0.5). Log `_slope_r2` on every fold and drop components that add a global offset.
- **de_score** depends only on which genes fall in the predicted top-n_up / bottom-n_dn, compared against an
  expression-level baseline. A no-change prediction scored -0.37 in simulation. A gene can be a down-hit only if its
  reference level is >= 0.25 (178-188 of 500 panel genes in the samples). `|lfc| >= 0.25` is applied to the **truth**
  only, so a composition-only prediction's small magnitudes cost nothing on de_score; only severity and the
  `std(dp) < 1e-8*std(dt)` zero-gate care about magnitude.
- **de_direction** rewards building deltas on the **full released reference**: predicted and true deltas share the
  server's 10% reference-subsample noise, so a prediction that is not exactly that copy picks up positive direction
  from noise alone (+0.2 to +0.5 for a plain copy at T1 sizes; a zero-biology prediction scored ~0.20). Consequences:
  a team-made "copy" is not the floor; the local harness must imitate the 10%/split-half protocol or local DE scores
  are biased; **never read de_direction > 0 as evidence that the direction is right**, especially on T3. Expected
  honest gain from this hygiene: +0.5 to +1 T1 point.
- **Variogram** over 32,285 genes is mostly a per-gene sparsity and marginal statistic: destroying all co-expression
  raised it ~2%, while kNN smoothing gave 7.4x and a constant added delta 2x. Pairs with one silent gene (~50%) carry
  53-56% of the score. Generate realistic sparse cells; never smooth, decode means or add log-space deltas.
  Caveat: the 75-cell probe numbers are noise-dominated; re-measure at real sizes on the released answers.
- **mmd_u** reflects composition and cell state; **neighborhood_mmd** is the only ranked term that notices expression
  shuffled away from position (18x worse, every shape metric unchanged).
- **neighborhood_mmd depends on submitted cell count** (15-NN profiles on the submitted cloud, no count matching).
  Two independent re-implementations agree on direction and disagree on magnitude by 2-3x; budget ~0.3-2 board points,
  and re-measure on real tissue after the release. The Data page's "no advantage to either end" does not hold here.
- **occupancy_dice** is sampling-density-limited (ceilings 0.766 / 0.880 / 0.9465 at 583 / 1,185 / 8,393 truth cells),
  subsamples to the smaller count, searches sign flips but not axis permutations, and rewards even point placement
  (Lloyd 0.926, farthest-point 0.921 vs a 0.908 ceiling at 583 cells). Treat blue-noise placement as an optional tweak
  to validate, not a planned gain; on shell-like tissue it is about +/-0.01 and can go negative.
- **Scorer build.** `pip install veckit` gives 0.1.2, which is the unmerged PR #6 code (severity_ratio, scale_ratio,
  size_fidelity) and lacks the right-handed-frame fix merged on main 2026-10-02. Pin git `cc3859a`. The live board
  still ranks `severity_slope` and `scale_log_ratio`. **Never install 0.1.2 anywhere, including the DGX**, and keep
  anyone building the size model away from it and from PR #6 ([removed: A] — the held-out geometry it contains).
- **Costs at server scale** (10% working copies): ~19 s per T1 board at ~5 GB RSS (48.6 GB without the subsample);
  the unranked frozen probe dominates T2/T3 at 40-99 s; emulate at 10% scale and cache truth-side work (~2-5 s per
  candidate).
- **Unknowns.** The server's subsample rule, seed and which half is truth; whether the test boards publish anything
  (the Evaluation page says calibration anchors are "validation boards only ... nothing about [the test boards] is
  published", so plan without test `truth_cells` or anchors); which replicate the T3 board ranks.

### 2.1 t1_methods — single-cell temporal prediction

**Key findings (allowed).**
- No published method is shown to forecast a future single-cell population better than naive baselines. Extrapolation
  benchmarks (scNODE 2024, scIMF 2025, scTimeBench 2026) compare deep models only with each other; most OT /
  flow-matching / Schrodinger-bridge work (WOT, moscot, TrajectoryNet, MIOFlow, VGFM, DeepRUOT, OT-CFM, MMFM, Light SB)
  was validated on interpolation in <=100 dimensions.
  *Verifier:* the narrow claim survives for pure forecasting, but is overstated for interpolation — Sunbear
  (Genome Res 2025) held out each time point of a large atlas and beat copy-previous/copy-next baselines on per-type
  pseudobulk correlation, and WOT Fig. S1F used copy-endpoint nulls. Sunbear's checkpoints are contaminated, but its
  evaluation design is a usable template. Minor fixes: scNODE's SC t=15 baselines were swapped in the report;
  scTimeBench has 10 methods (8 forecasting + 2 OT), and the group trailing scIMF is MIOFlow/OT-CFM/scNODE.
- In VEC itself the organisers' neural ODE does not beat a constant shift, and `pseudobulk_shift` scores 48.58
  (variogram skill 38.9), below copy_last's 50; the variogram costs it ~2.2 points. Best T1 validation entry and
  per-metric maxima (human-track variogram max too), confirmed exactly against the live API:
  [per-board leaderboard figure removed 2026-11-05; docs/DATA_POLICY.md 2026-11-05 (h)].
- Waddington-OT's own validation: OT interpolation is about as accurate as a batch-to-batch baseline at 1-day gaps and
  degrades at 2 days. moscot's `TemporalProblem` offers the same validators but interpolates by a dense linear blend —
  generate in count space instead.
- Released `.X` is exactly `log1p(1e4*c/N)`; integer counts and depth are recoverable (median ~11K UMIs, 10th-90th
  ~6.2K-22K, ~88% zeros). Verified independently (max deviation from integer 1.2e-4; round with 1e-3 tolerance).
  Mito ~6%, Rps/Rpl ~13%, Malat1 0.33% indicate whole-cell-like RNA despite Multiome chemistry.
- Dense outputs ruin the variogram. The report's count-space figure came from a biased target
  (`expm1(mean log1p)`); with a correct linear-scale mean-ratio target the verifier's run gives systematic error
  2.3e-4 vs 7.4e-4 for copy, so count-space edits do help **when the target is specified correctly**.
- **Legal bracketing data exist** (this is the decisive lever: turn extrapolation into interpolation):
  Feng 2022 (GSE193346), 10x 3' v3 chamber-dissected hearts — E9.5 and E14.5+ legal; JAX/Qiu 2024 time-lapse
  (11.44M nuclei after QC, 24,552 genes, median 2,545 UMIs) — E9.5 and earlier, E13.75 and later.
  *Verifier corrections:* Feng E9.5 exists only in CD1 (887 cells, 78% ventricular CM, median ~31.8K UMIs; C57BL/6

### 2.4 t3_methods — knockout prediction

**Key findings (allowed).**
- **The "add a pseudobulk delta then clip at zero" construction is mechanically broken on sparse MERFISH.** It
  realises a median 4% (p90 22.7%) of an intended decrease but 100% of an increase, and the realised decreases
  correlate r = 0.992 with WT pseudobulk level — which is exactly the expression-magnitude null that de_score
  subtracts and de_direction partials out. *Verifier:* do not cite r = 0.992 as general (it holds for a uniform
  delta; Spearman 0.78-0.93 for heterogeneous ones), but the conclusion stands: never add log-space deltas; generate
  real or count-sampled cells.
- **Public board evidence:** `shift_transfer` 42.48 and `gene_ko` 42.50; a public competitor log's scores
  ([per-board leaderboard figure removed 2026-11-05; docs/DATA_POLICY.md 2026-11-05 (h)]) show that mixing 70% real
  cells from the released training knockout with 30% WT beat the additive global delta, and every per-gene transform
  family collapsed the variogram. Its best later entry came from cell-type flattening plus WT dilution — so it is
  *which* cells and in what proportion, not "real cells" as such. [removed: B — a claim in the same source about how the
  Gata4 knockout response relates to the training knockout's response.] (Competitor repos are unlicensed: ideas only.)
- **Deep perturbation models do not beat simple baselines** (Ahlmann-Eltze 2025: no model beat additive/mean/linear;

  knockouts, skip GEARS/CPA/scGen/CellOT/biolord/PerturbNet/State/scGPT. VCC 2025 was won by hybrid
  statistical/deep systems tuned to the metrics.

### 2.5 t3_biology — what may be used for the knockout board

Most of this dimension was gene-level literature on the held-out genotypes and has been removed. What survives:

- **Target facts.** Test condition: Mesp1-Cre; beta-catenin F/F at E8.75, 2 replicates (never released). Validation:
  Mesp1-Cre; Gata4 F/F; Gata6 F/+ at E8.75, 2 replicates, answers released 2026-10-20. Training knockout: Mab21l2 at
  E9.5 (allele not stated). Reference: matched WT at E8.75 (shared with the T2 heart setting) and at E9.5. Panel: the
  500-gene MERFISH panel, identical to T2-heart. Scored: de_score 0.30, de_direction 0.25, |severity_slope| 0.25,
  mutant-state distribution 0.20.
- **Why the rule bites hardest here.** The scored quantities are per-gene signs and ranks of the pseudobulk change, so
  a hand-written gene-direction table is close to the scored answer itself. Every gene direction must be derived from
  released data by the pre-registered procedure in `docs/PLAN.md` section 4.4.
- **Broad phenotype (allowed).** Mesodermal beta-catenin loss around E8.5-E9.5 is a second-heart-field expansion
  failure: the outflow tract and right ventricle are hypoplastic and looping is disrupted, while the first-heart-field
  / left-ventricle component is comparatively preserved; progenitor proliferation is reduced. It reads as a growth and
  allocation defect, not a specification or differentiation failure, so at E8.75 the mutant heart should look visibly
  abnormal but not lose cardiomyocyte identity. Beta-catenin is also an adherens-junction component, where the changes
  are largely at protein level. The validation genotype is expected, at the same broad level, to give thin myocardium,
  right-ventricular hypoplasia and reduced cardiomyocyte proliferation; the two knockouts partly phenocopy each other
  at this level, which is why the released Gata4 data is the best legal calibration for the test board.
  *Verifier cautions:* the stage mapping tightens rather than loosens the problem (plan on an arrested or
  near-arrested mutant at the test stage, not a mildly abnormal one); a per-cell proliferation signature should be
  demoted — the proliferation deficits in the literature are measured at other somite stages; and the "protein-level,
  not transcriptional" junction statement is an inference, not a finding.
  [removed: B — the gene-level direction tables, named genes and the publications behind all of this.]
- **Mesp1-lineage scope (lineage biology, not knockout data).** Mesp1-Cre labels early cardiac and cranial mesoderm and
  their derivatives — heart-tube myocardium, endocardium, pericardium/proepicardium, pharyngeal mesoderm, extra-embryonic
  mesoderm — and labels trunk paraxial mesoderm poorly. Endoderm, surface ectoderm, neural tube and neural crest are
  not Mesp1-derived. Non-lineage compartments therefore estimate nuisance (depth, coverage, staging, batch) plus

  matched WT carries Cre is not stated. *Verifier:* the "poor trunk paraxial labelling" claim rests on a

  signal is a septum-transversum / proepicardial deficit (smaller Tbx18+/Wt1+ proepicardium, reduced Itga4), with

  reported absent from the septum transversum mesenchyme at E9.5 would make its pseudobulk fall, not stay flat, if the

  within-type term. Halving a compartment at fraction f with within-type mean m moves the pseudobulk by ~0.5*f*m —

  report claimed (verified numerically). More importantly, that threshold applies to the truth only, so a
  composition-only prediction's small magnitudes cost nothing on de_score.
  [removed 2026-11-05: a possible property of a hidden target] of 500 genes are truth DE on the T3 board.

### 4.1 T1 E12.5 composition prior (gap 1) — the largest single T1 lever

**Question.** Given a heart-chamber-only E12.5 dissection, what composition should the two T1 submissions assume, and
what does each composition error cost?

**Findings** (pseudo-task through the pinned scorer, 8 seeds; reference and copy_last E8.5, truth one E9.5 library cut
to heart-chamber classes plus contamination):
- **Scope re-weighting dominates.** Re-weighting real reference-stage cells to the chamber-only composition, with no
  state change at all, moves T1 from 51.1 to 74.8 (+23.7 +/- 0.5); +12 to +26 across 11 truth variants; +14.3 with an
  E10.5-like thinned reference. It recovers de_score 0.49 of an attainable 0.87 and brings mmd_u to 0.028 against a
  0.092 floor.
- **Drop the second-heart-field, pericardial and pharyngeal types as well as the surrounding tissue.** Dropping only
  surrounding tissue gets +13.5 of the +23.7; dropping the SHF/pericardium/pharyngeal group too gets +23.4. Keeping
  that group at the reference share (39%) costs 13.3 points; dropping it when the truth retains 15% costs only 0.9-3.1.
- **Cost of composition errors** (oracle / realistic state families): non-cardiac over-predicted +10 costs 1.6-2.7 /
  ~0; under-predicted -10 costs 3.8-5.5 / 2.8-3.3; blood over-predicted +10 costs 6.6-8.0 / 3.0-3.1; CM share +/-10
  costs 2.1-5.2 / -0.2 to +2.5; keeping SHF/pericardium when the truth has none costs 2.1 / 1.3 at +10. Errors are
  roughly additive and ~1.2-1.7x dearer with a closer reference. Within +/-5 points, composition choices are nearly
  free.
- **The CM share of heart cells carries ~75% of the composition risk** and is the real unknown: legal E14.5 data
  disagree (one whole-heart dataset [value redacted 2026-11-05: its sample is coded Theiler stage 22, which the
  staging rule keeps out; `docs/DATA_POLICY.md` 2026-11-05 (e)], one chamber dataset 41.5% in one strain and 76.6% in
  the other, ventricle-weighted).
- **Blood:** T1 is single-nucleus, so whole-cell blood fractions do not transfer (blood is 1.6% of nuclei at E8.5 and
  1.25% at E9.5, against 10.0% whole cells in an external E9.5 heart). Set ~1.5-2%; over-predicting by 10 points
  costs 6.6-8.7.
- **Births of emergent states** add +1.7 / +3.3 / +8.7 points at 4.7% / 9.3% / 18.7% emergent share with perfect
  states; nearest-progenitor proxies capture 33-41% of that, same-stage wrong-type mesenchyme 60-78%; births at double
  the true share cost -4.4. Within-type state quality is worth 15-17 points. **Order the work: scope (~+20), then
  per-type state shifts (~15), then births (~1.5-5).**
- **Proposed s1** (share of all cells): CM 54, endocardium 20, epicardium 7, mesenchyme 9, vascular EC 2, immune 1,
  blood 2, esophagus-junction contamination 5, SHF/pericardium 0 — i.e. CM 58% of heart cells. **s2** identical with CM
  at 70% of heart cells. Expected best-of-two gain ~1.1-1.4 points; the hedge belongs on the CM share, not the
  non-cardiac fraction.

**Actions.** Rebuild the base model as chamber-only re-weighting of real E10.5 cells plus the count-space momentum
shift (prio 1). On 2026-10-20 classify the E10.5 types from markers, re-run the pseudo-task with E10.5 as reference,
re-fit the three-point trends and commit the s1/s2 rule before any upload (prio 1). Register the external label
metadata in `EXTERNAL_DATA.md` with the committed window filters **before** the prior enters a submission (prio 1).
Make s1 and s2 differ only in the CM share (prio 2). Spend effort on per-type state shifts before births; add cheap
proxy births first (prio 2). Re-word the assumption ledger so the hedge brackets the CM share (prio 2). Ask the
organisers whether qualitative in-window developmental background may define the E12.5 class list, and confirm the
E14.5 external hearts are acceptable (prio 3).

### 4.2 T3 response decomposition (gap 2) — what actually carries the knockout response

**Question.** Under the official metrics, which components carry a real knockout-vs-WT MERFISH response — section
coverage, lineage composition, developmental-stage offset, depth, or within-type change — and does a blind rule based
only on the broad phenotype recover its sign? Run it now on the released training knockout, and pre-register the same
script for the Gata4 answers.

**Findings** (released Mab21l2 knockout vs WT E9.5, 10 seeds of the 10%-subsample / split-half protocol, official
metrics):
- **The response is mostly one per-gene factor shared by every cell type.** Estimated from the five non-lineage types
  only and applied to WT cells, it alone scores T3 79.3 (de_score 0.46, de_direction 0.30, log beta -0.17, R^2 0.60,
  DE sign agreement 0.80), against 59.5 for the knockout's full harmonised composition (ceiling 86.4, floor 50.0). In
  a joint non-negative fit of the true delta, dropping it costs R^2 0.52; dropping composition costs 0.04.
- **Coverage** (WT resampled to the knockout's non-lineage proportions) is worth +4.5 T3 alone and nothing once the
  factor is present. **Lineage composition** adds +6.0 on top of coverage and +1.5 after the factor — the only
  composition term that survives. **Stage axis** has a stable offset but adds nothing after the factor (it probably
  aliases the WT reference's own quirks). **Depth** alone, or with composition, adds a near-uniform upward shift that
  puts severity at its floor in 10 of 10 seeds; it helps only together with the factor. **Within-type change** is
  almost all the shared factor: the type-specific remainder is 6.5% of the delta with chance-level sign.
- **The blind broad-phenotype rule fails.** Depleting the compartments the phenotype predicts gives de_direction
  0.065-0.077 against 0.059 for plain WT resampling, with severity at the floor in 8-9 of 10 seeds; the harmonised
  composition even moves against the rule. On top of the factor the rule is harmless (+0.55) but useless without it.
- **The plan's component as written** (real non-lineage knockout cells plus WT lineage cells) scores 66.1; the same
  information applied as a per-gene factor to all WT cells scores 79.3 (+13.3, paired t 30.7).
- The factor is roughly half knockout-specific and half WT-reference-specific (independent-offset variances 0.29 and
  0.27), so the WT part transfers to the beta-catenin board for certain and the knockout part only if the series
  shares a batch.
- **Label names are misleading across files:** a marker-based crosswalk and a WT-trained classifier agree on 14 of 15
  knockout labels (CV accuracy 0.83), and three knockout labels map to different WT names. Use classifier relabelling.
- **The released files contain duplicated cells** (2,811 in the training knockout, 868 in WT E8.75, 1,281 in
  E8.25_late; none in WT E9.5). Deduplicate before building pools and before local split-half ceilings, and check the
  Gata4 and beta-catenin files on release.

**Consequences for the two beta-catenin submissions.** Both should carry a per-gene factor; they should differ in how
it is **sourced** (full Gata4 factor plus Gata4 depth, versus a reference-only factor built from the WT series), not
in coverage or composition sign. Composition rides on top of the factor in both, at a magnitude calibrated on Gata4,
and its sign is hedged only if the pre-registered decision rule says so. A pure coverage scenario is not worth a
submission. Depth enters only with the factor. The pathway-programme component stays low priority unless the
corresponding rule fires on Gata4.

**Actions.** On 2026-10-20 run the frozen script unchanged on the DGX against both Gata4 replicates (sha256 recorded;
~45 min CPU plus reading) and read its decision file (prio 1). Commit the frozen script to the repo before downloading
the Gata4 files, as a timestamped pre-registration (needs the user's go-ahead; prio 1). Re-implement the plan's
component as a count-space per-gene factor applied to all WT E8.75 cells, with per-type depth only alongside it
(prio 2). Update the assumption ledger (the ledger's proxy tests the wrong lever if Gata4 behaves like the training
knockout) and fix the "27% deeper" depth model to per-type depth ratios (prio 2). After E10.5 and E8.5 are released,
run the stage-axis diagnostic to tell reference idiosyncrasy from a real developmental delay (prio 3).

**Caveats.** One embryo, one batch; the training knockout has no heart defect at its stage, so its composition signal
should be smaller than the two evaluation knockouts' — Gata4 is the real readout. "Per-gene factor" is a description,
not a mechanism (probe or imaging efficiency, segmentation spillover, ambient RNA or a global biological effect would
all look like this; only the first three plausibly transfer across a knockout series). Absolute scores are emulator
scores with computed anchors, not board scores. Littermate WT cells, if present, would separate batch from genotype
directly.

### 4.3 External-direction concordance (gap 3) — does legal external data carry usable direction?

**Question.** Do within-dataset fold changes from legal external heart data agree in direction with changes in our own
data, cell type by cell type, and do they beat damped internal momentum?

**Data used (all legal):** T1 E8.5/E9.5; JAX embryos 1-22 and 54-74; Feng CD1 E9.5 and stages from E14.5. No E10.5 or
E12.5 data.

**Findings.**
- **Platform matters.** T1 behaves like whole-cell 10x data (mito 6.1%, Rps/Rpl 12.3% at E9.5 for CM) and matches Feng
  (profile Spearman 0.83-0.89) far better than JAX nuclei (0.63-0.67).
- **JAX, same interval, per harmonised cardiac type:** sign agreement 0.62-0.89 (median 0.73), Spearman 0.33-0.69
  (median 0.42), against a technical-replicate ceiling of 0.94-0.99 / 0.80-0.92. At the population level the scorer
  would see de_score 0.11 / de_direction 0.21 (cross-run) against a within-type oracle of 0.68/0.74 and a
  composition-only oracle of 0.38/0.60; shrinkage does not help. JAX early contrasts are run- and depth-confounded
  (~6.5-9.3K UMIs vs 1.4-3.6K), and the late windows look batch-dominated.
- **Feng, within platform, cross-fitted, legal late stages only:** the bracket direction beats internal momentum by a
  wide margin. Test-like geometry (2-day step, t~0.5, external start one stage early): sign 0.92 vs 0.73, Spearman
  0.80 vs 0.40, de_score 0.40 vs 0.13, de_direction 0.24 vs 0.09, against a replicate ceiling of 0.91/0.82/0.24/0.46.
  Val-like geometry (1 day): sign 0.83 vs 0.60. Adding momentum adds nothing.
- **The long-range direction is platform-robust:** JAX vs Feng over the same bracket agree at sign 0.82-0.91 and
  Spearman 0.68-0.72 given enough late cells, dropping to 0.67-0.72 where JAX has few heart nuclei.
- **Our momentum agrees with the Feng bracket for cardiomyocytes** (sign 0.73, Spearman 0.45) **but not for
  endocardium** (0.50/0.10), so the Oct 20 test will discriminate.
- **Our own stage contrasts carry non-developmental pool effects** (sex-linked and strain-polymorphic genes), and the
  two T1 libraries per stage are technical splits, so the "replicate ceiling" is optimistic.
- A fully legal ingestion route exists: per-embryo count files for the legal JAX embryos only, so no in-window
  expression is ever downloaded.

**Verdict and actions.** Concordance is neither near-zero nor high, and depends on platform. **Drop JAX as a T1
direction source** (prio 2) and do not ingest the 40-60 GB set. **Build the Feng-direction variant now** (prio 3,
1-3 days; stats already on the DGX). **Defer the OT-bracketing pipeline** until the Oct 20 readout of the ready script,

genes flat in every T1 prediction (prio 2). Register both sources in `EXTERNAL_DATA.md`, move the filter scripts into
the repo, and quarantine the raw external object that still contains in-window cells (prio 2). Keep the legal
within-Feng late-stage backtest as a standing harness (prio 5).

**Open questions.** Whether the external direction beats cross-fitted momentum on our own next transition. The
cross-dataset cost between the challenge lab's cells and the external cells. Whether the within-platform bracket
advantage measured at late fetal stages holds across the test window. The E10.5 label vocabulary. How much of the

### 4.4 T2 units, scale and shape (gap 4) — what the heart and embryo size models may rest on

**Question.** What are the per-stage physical scales of x, y and z in the released MERFISH files; with harmonised

**Findings.**
- **xy are slide micrometres.** In every wild-type file each section's 3D xy is a pure translation of the 2D slide
  coordinates (rotation 0, scale 1.000000, residual <= 1.4e-10), and the slide layout matches a commercial MERSCOPE

- **z is (serial section position) x a per-file step**: 10 at E6.75, E7.25 and the released knockout; 14 at E8.75;

- **The stored step is most likely the physical section pitch in micrometres** [Medium]: the public sample files show

### 4.5 Scorer build and dice handedness (gap 5)

**Question.** Which veckit build does the live server run, and what does handedness do to `occupancy_dice`?

**Findings.**
- **The live validation scorer behaves like the pre-fix build** (the maintainer's stated target version, also the PyPI
  release), not like git main. Ten geometry groups on the three T2 boards were scored before the handedness fix was
  merged (2026-10-02) and again in October with rescaled or changed files, and their `occupancy_dice` is identical to
  4 decimals in all ten; a switch would change each with probability ~1/2, so a switch before 12 October has
  probability <= 0.008 and before 16 October <= 0.03. A switch in the last two days, or for the final evaluation,
  cannot be excluded. The published shape anchors were already present in a 2026-09-03 community copy and are
  unchanged, so they were baked pre-fix and never regenerated — although the fix's reviewer said they would need to be.
- **The task premise was wrong in an important way: under the live build a mirror twin scores exactly like the
  original** (380/380 cases). What moves Dice is a fair coin from the SVD sign pattern, set by row order and rotation:
  each file lands on either the proper-mode or the mirror-mode value. The coin is identical across OpenBLAS kernels,
  thread counts and two numpy versions (MKL and Accelerate untested), and permuting rows flips it 47-55% of the time
  on all seven released stages.
- **Size of the effect** on E9.5 at the heart-extrapolation board's density (8,393-cell halves): the proper-minus-mirror
  Dice gap is 0.133 for a perfect shape, 0.101 / 0.056 / 0.032 / 0.011 under 0.1 / 0.2 / 0.3 / 0.5 RMS jitter, 0.076 for
  a 10% stretch, and ~0 for copy-like shapes — up to ~3.5 heart-board points,
  [per-board leaderboard figure removed 2026-11-05; docs/DATA_POLICY.md 2026-11-05 (h)] at leader-level Dice, ~1.4 on
  the embryo board near its ceiling. **The stakes grow with shape quality.**
- **The right hedge is a parity hedge, not a mirror hedge:** two files with opposite local parity, the same cell count
  and the same row order. It is free under the fixed build and guarantees one proper-mode file under the live one
  (assuming the server's metric seed is 0, which the evidence supports but does not prove; otherwise coverage falls
  from 1 to 3/4).
- **All released heart reconstructions share one anatomically correct handedness** by a left-sidedness marker triple
  product (laterality markers agree at the earliest embryo stage); whole-cloud ICP was inconclusive. So under a fixed
  build a prediction built from released stages by proper transforms should already have the truth's handedness.
- The server uses a **fixed metric seed**: identical files from different teams and dates give identical seeded
  metrics, and rescaled copies keep identical d2 and mmd_u. This contradicts a relayed organiser remark that the seed
  would depend on each submission.

**Actions.** Ask the organisers (GitHub issue on the scorer repo, or a reply to the 10-18 email) which
canonicalisation the test boards and the final evaluation will use and whether anchors will be re-baked — our question
5 only covers the metric change (prio 1, needs the user's approval to post). Add a scorer-build switch to the emulator,
defaulting to pre-fix to match the live board, and report proper-mode Dice, mirror-mode Dice and local parity per
candidate (prio 1). Use the parity hedge on each T2 test board; switch to a mirror hedge only if handedness becomes
doubtful under a fixed build (prio 2). On 2026-10-20 run the ready anchor-check script against the released answers to
find the exact bake protocol, classify each Dice anchor as proper- or mirror-mode, and measure the real mirror and
coin effect (prio 2). Re-run the handedness check on the newly released stages (prio 3). Amend the plan's "proper
rotations only" rule to add the parity behaviour, and treat other teams' Dice scores as coin-noisy (prio 3).

**Limits.** Whether the server switched builds in the ~48 h before the snapshot cannot be excluded. The seed is
assumed to be 0. The server's LAPACK sign convention is assumed OpenBLAS-like. E12.5 handedness cannot be checked.
**Note on method ethics:** the parity hedge uses no score returns and only orients our own prediction, so it is likely
legitimate, but it deliberately exploits a known scorer defect — disclose it, or ask the organisers in the same
message. A two-file probe that would determine the build from score differences was explicitly **not** recommended, as
it conflicts with the team's no-differencing invariant.
