  The same cells in the same order, the same names and coordinates; the expression of 84 cells differs (5,041 entries
  of the matrix). The factor record is identical on both machines apart from the input files' paths: 12 lineage groups
  with their own factor, SD of the pooled log factor 0.5359908127886033, 16 genes at the clip, exponent 0.5.
  The cause, checked on the released WT E8.75 pool alone (23,377 cells after the duplicate filter): the builder smooths
  each cell's profile over its 15 nearest neighbours in a 30-component PCA (t3_decompose.smoothed_props). The counts
  and the log-normalised values are identical on both machines; the PCA scores differ by up to 3.3e-4 (typical size
  2.5), because the local machine (AMD EPYC 7742) runs OpenBLAS's Haswell kernel and the DGX (Xeon Platinum 8468) its
  SkylakeX kernel. So 10 cells get another neighbour set and 3 another smoothed profile, and the Poisson top-up of the
  genes whose factor is above 1, which draws from that profile, then draws differently for the 84 cells. Neither file
  is wrong; they are two draws of the same construction. The uploads are built on the DGX, so the DGX's hash is the
  reference. T3's first-choice file (allowed s1) uses the same smoothing and reproduces its DGX archive.
